# ارزیابی گفتار فارسی 4B-MOS — مرحله مقایسه متن

این مرحله بدون کامپیوتر جدید یا اطلاعات بیمار واقعی قابل اجراست. ابزار مقایسه متن ساخته شده است؛ هیچ اجرای مدل گفتار، ضبط واقعی، آموزش شخصی پزشک یا تأیید دقت بالینی در این مرحله انجام نمی‌شود.

## دو نوع اندازه‌گیری

۱. **فاصله اصلاحات پزشک:** API متن ماشینی و آخرین متن مرورشده مربوط به همان پیش‌نویس را مقایسه می‌کند. این مقدار میزان تفاوت نوشتاری را نشان می‌دهد. پزشک ممکن است متن را خلاصه یا بازنویسی کند؛ بنابراین این مقدار، نرخ خطای واقعی گفتار نیست. متن اصلاح‌شده به‌عنوان مرجعِ تأییدشده مستقل از صوت معرفی نمی‌شود.

۲. **مقایسه با متن مرجع:** ابزار آفلاین برای مجموعه آزمایشی، متن مرجع و متن خروجی را می‌گیرد و فاصله را محاسبه می‌کند. در داده واقعی، مرجع باید با شنیدن صوت و بررسی انسانی تهیه شده باشد. پذیرش یک اعلام در فایل JSON، راستی‌آزمایی کیفیت آن مرجع نیست. مجموعه ساختگی همراه پروژه فقط رفتار نرم‌افزار سنجش را آزمایش می‌کند؛ خروجی‌های آن از موتور گفتار نیامده‌اند.

## معیارها

- فاصله واژه‌ای، حداقل تعداد درج، حذف و جایگزینی برای تبدیل یک متن به دیگری است. نرخ، فاصله تقسیم بر تعداد واژه‌های مرجع است. این نرخ ممکن است بیشتر از ۱۰۰٪ باشد؛ «۱۰۰ منهای نرخ خطا» دقت بالینی محسوب نمی‌شود.
- فاصله نویسه‌ای همین مقایسه را پس از حذف فاصله بین واژه‌ها انجام می‌دهد. نویسه‌های یونیکد شمرده می‌شوند، نه شکل‌های گرافیکی مرکب.
- نسخه `fa-text-v1` شکل‌های عربی ک/ی، ارقام فارسی/عربی، کشیده، حرکات و نیم‌فاصله را یکسان‌سازی می‌کند. حروف لاتین کوچک می‌شوند؛ نشانه‌گذاری حذف می‌شود، اما علامت عدد، ممیز و اسلش عددی حفظ می‌شوند. این قواعد، تحلیل معنایی یا بررسی واحد دارویی نیستند و ممکن است بعضی تفاوت‌های مهم را پنهان کنند. متن اصلی هیچ‌گاه با متن نرمال‌شده جایگزین نمی‌شود.
- تغییر توالی اعداد، افزودن یا حذف عدد و تغییر شمار حضور عبارت‌های حساس مشخص‌شده در مرجع گزارش می‌شود. جابه‌جایی ترتیب اعداد نیز قابل تشخیص است. این بررسی هویت بیمار، دارو، دوز یا معنای جمله را تشخیص نمی‌دهد.
- نمونه عبارت حساس: واژه منفی، سمت راست/چپ یا نام ساختگی در متن آزمون. عبارت باید در مرجع حضور داشته باشد. بررسی به حضور دقیق توکن‌ها محدود است؛ همه خطاهای بالینی را کشف نمی‌کند.
- گزارش شامل شمارش‌ها و هش متن است؛ متن خام و عبارت حساس در خروجی گزارش نوشته نمی‌شوند. شناسه مجموعه و نمونه باید مستعار باشند. هش‌ها هم ممکن است در کنار داده دیگر قابل تطبیق باشند؛ گزارش را عمومی نکنید.
- امتیاز صفر، مجوز عبور از مرور صوت یا انتشار بالینی نیست. هیچ آستانه‌ای خودکار مجوز انتشار، تشخیص یا آموزش صادر نمی‌کند.

## API متصل به ضبط موجود

`GET /api/v1/visits/{visit_id}/recordings/{recording_id}/media/text/revision-metrics`

فقط پزشک ضبط‌کننده، با تخصیص فعلی و رضایت معتبر دقیق همان ضبط، اجازه دریافت دارد. پیش‌نویس و متن مرورشده متناظر لازم‌اند. پاسخ متن خام ندارد، `no-store` است و هیچ رویداد جدیدی در پرونده ایجاد نمی‌کند. هش دو نسخه در پاسخ، مقایسه را به همان نسخه‌ها متصل می‌کند. متن بیش از ۵۰٬۰۰۰ نویسه، قبل یا بعد از نرمال‌سازی، برای این محاسبه محدود رد می‌شود؛ این محدودیت، سقف نگهداری متن ویزیت را تغییر نمی‌دهد.

این مرحله API و ابزار ارزیابی را اضافه می‌کند؛ صفحه ویندوز ۰٫۲ هنوز این امتیازها را نمایش نمی‌دهد و نسخه اجرایی آن تغییر نکرده است.

## اجرای نمونه ساختگی

با محیط معمول backend، بدون نصب مدل گفتار:

```bash
python -m backend.tools.speech_evaluation \
  backend/tests/fixtures/speech_benchmark_synthetic.json \
  --output /tmp/4b-synthetic-speech-report.json
```

مسیر خروجی باید جدید باشد؛ ابزار فایل قبلی یا ورودی را بازنویسی نمی‌کند. ورودی حداکثر ۲۴ مگابایت، ۲۰۰ نمونه، هر متن حداکثر ۵۰٬۰۰۰ نویسه و هر نمونه حداکثر ۳۰ عبارت حساس دارد. شناسه تکراری، مرجع فاقد توکن، مرجع تأییدنشده و استفاده تأییدنشده رد می‌شوند. پیام خطا متن ورودی را چاپ نمی‌کند.

ورودی JSON شامل `dataset_id`، `dataset_kind`، `authorized_for_evaluation: true` و `cases` است. هر نمونه `case_id`، `category`، `reference_verified: true`، `reference`، `candidate` و در صورت نیاز `protected_phrases` دارد. نوع مجموعه فقط `synthetic` یا `approved_deidentified` است. برای داده واقعی، این اعلام‌ها باید بر یک روند واقعی رضایت، مجوز استفاده و حذف هویت تکیه داشته باشند؛ ابزار خودش صوت را صادر یا داده را بی‌هویت نمی‌کند. فایل خام واقعی در GitHub ثبت نشود.

## مسیر آماده‌سازی ارزیابی ۲۰۰ ویزیت

۱. ابتدا با گفتگوی ساختگی در اتاق، اتصال میکروفن، صدای هر دو طرف، نویز و قطع ارتباط را بررسی کنید. نمونه متن همراه پروژه جای ضبط صوت را نمی‌گیرد.
۲. بانک پرسش‌ها و ترتیب معاینه هر پزشک را از خود پزشک جمع‌آوری و در بانک خصوصی موجود ثبت کنید. سبک پزشک و صحت پزشکی دو موضوع جدا هستند.
۳. نمونه‌های واقعی را تنها پس از اجرای روند رضایت و مجوز استفاده جمع‌آوری کنید. صوت، مشخصات بیمار و شناسه هویتی از مجموعه گزارش جدا بمانند.
۴. نسخه مدل و هش وزن‌ها، شرایط ضبط، پزشک، نویز و روش تهیه مرجع را در دفتر ارزیابی مجاز نگهداری کنید. هر خروجی مدل با همان متن مرجع مقایسه شود؛ نمونه‌های سکوت و متن خالی نیز بررسی شوند.
۵. نمونه‌های مربوط به یک بیمار در مجموعه آموزش و ارزیابی مشترک قرار نگیرند. مجموعه ارزیابی کنار گذاشته شود و برای تنظیم سبک پزشک استفاده نشود.
۶. خطاهای اعداد، منفی‌بودن عبارت، سمت بدن و اصطلاحات جداگانه با شنیدن صوت مرور شوند. معیار پذیرش پس از دیدن خطاهای واقعی و توسط پزشک مسئول تعیین شود.

عدد ۲۰۰ هدف اولیه جمع‌آوری شماست؛ این تعداد به‌تنهایی کفایت تنوع، دقت مدل یا ایمنی استفاده را اثبات نمی‌کند. خروجی این مرحله زیرساخت اندازه‌گیری است؛ آغاز مطالعه واقعی و شخصی‌سازی مدل هنوز انجام نشده است.
