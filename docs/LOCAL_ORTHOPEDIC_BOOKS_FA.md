# خواندن مستقیم کتاب‌های ارتوپدی از هارد

این ابزار باید **روی همان رایانه‌ای اجرا شود که کتاب‌ها روی آن هستند**. اجرای آن در سرور ابری به درایو D رایانهٔ شما اتصال ایجاد نمی‌کند. خود ابزار فایل و متن را محلی نگه می‌دارد؛ برای ادامهٔ تحلیل بدون بارگذاری دستی فایل‌ها، پوشهٔ پروژه و خروجی را در Codex محلی همان رایانه باز کنید. استفادهٔ بعدی از مدل تابع تنظیمات همان برنامه است؛ ابزار استخراج هیچ مدل یا API را فراخوانی نمی‌کند.

## وصل کردن پوشه‌ها به پروژهٔ محلی

طبق [راهنمای رسمی پروژه‌های محلی](https://learn.chatgpt.com/docs/projects)، در برنامهٔ دسکتاپ یک Local project ایجاد کنید و از منوی پروژه، `Edit project` و سپس `Add folder` را بزنید. پوشهٔ محلی مخزن 4B-MOS را به‌عنوان پوشهٔ اصلی و `D:\orthopedic book` را به‌عنوان پوشهٔ دوم اضافه کنید. پوشهٔ خروجی خصوصی ابزار نیز در ادامه می‌تواند اضافه شود.

در **همان پروژهٔ محلی یک گفتگوی جدید** شروع کنید و دستور بخش «ادامهٔ تحلیل» را بدهید. تاریخچهٔ گفتگوی ابری یا sync شدن آن به‌تنهایی دسترسی به هارد نمی‌دهد؛ این نشست ابری همچنان فایل‌های درایو شما را نمی‌بیند. در دستور خود تصریح کنید که کتاب‌های اصلی فقط خوانده شوند و تغییر نکنند.

## اجرای ساده در Windows

1. آخرین نسخهٔ شاخهٔ `feature/orthopedic-intelligence` را در رایانه دریافت و ZIP مخزن را کامل Extract کنید. فقط فایل CMD را جدا دانلود نکنید؛ پوشه‌های همراه آن لازم‌اند.
2. Python نسخهٔ 3.12 یا جدیدتر باید نصب باشد.
3. در پوشهٔ اصلی پروژه، روی `Read-Orthopedic-Books.cmd` دوبار کلیک کنید. مسیر پیش‌فرض `D:\orthopedic book` است. برای مسیر متفاوت می‌توانید پوشهٔ کتاب‌ها را روی فایل CMD بکشید و رها کنید یا در Command Prompt اجرا کنید:

```bat
Read-Orthopedic-Books.cmd "D:\orthopedic book"
```

راه‌انداز یک محیط جدا در `.venv-books` می‌سازد. فقط نصب اولیهٔ کتابخانهٔ اختیاری `pypdf` نیاز به دانلود دارد؛ خواندن و استخراج کتاب‌ها بدون ارسال فایل یا تماس شبکه انجام می‌شود. دسترسی Administrator، اجرای backend، ورود به پایگاه داده یا تغییر ExecutionPolicy لازم نیست.

محل خروجی پیش‌فرض:

```text
%LOCALAPPDATA%\4B-MOS\orthopedic-library\run-...
```

در پنجرهٔ اجرا، مسیر دقیق `report.txt` و `manifest.json` نمایش داده می‌شود. هر اجرا پوشهٔ تازه می‌سازد و کتاب اصلی یا خروجی اجرای قبلی را تغییر نمی‌دهد.

## خروجی واقعی این مرحله

- `manifest.json`: فهرست PDFها و فرمت‌های کتاب پشتیبانی‌نشده، هش کامل فایل، اطلاعات metadata با برچسب تأییدنشده، وضعیت خواندن، نسخهٔ ابزار و نسخهٔ استخراج‌کننده.
- `books/<file-sha256>/pages.jsonl`: متن محلی هر صفحه با شمارهٔ یک‌مبنای صفحهٔ PDF، برچسب صفحه در PDF در صورت وجود، هش متن و وضعیت استخراج.
- `report.txt`: گزارش خوانا از موفقیت، فایل تکراری، خرابی، رمزگذاری، محدودیت اندازه/صفحه و نیاز به بازبینی.

هش خود manifest، فایل کامل صفحات و فایل ابزار نیز ثبت می‌شود؛ هش فایل صفحات علاوه بر متن، ترتیب و ارجاعات صفحه را پوشش می‌دهد. برای بررسی مجدد یک خروجی محلی بدون خواندن PDF اصلی:

```bat
.venv-books\Scripts\python.exe backend\tools\local_orthopedic_library.py --verify "C:\Users\YOUR-NAME\AppData\Local\4B-MOS\orthopedic-library\run-..."
```

این بررسی یکپارچگی snapshot استخراج است؛ به‌معنی تأیید کتاب، ارجاع چاپی، صحت متن یا اعتبار پزشکی نیست.

عنوان یا نویسندهٔ metadata، تاریخ ایجاد PDF، نام فایل و برچسب صفحه جای تأیید عنوان، ویرایش، سال انتشار یا شمارهٔ چاپی صفحه را نمی‌گیرند. شمارهٔ فصل استخراج نمی‌شود و باید بررسی شود. کتاب‌های تکراری با هش یکسان فقط یک بار استخراج می‌شوند. لینک‌ها و junctionها برای دسترسی به پوشه‌های دیگر دنبال نمی‌شوند.

صفحهٔ بدون متن الزاماً اسکن نیست؛ با وضعیت نیازمند OCR **یا بررسی دستی** گزارش می‌شود. این نسخه OCR ندارد. PDF رمزدار باز یا دور زده نمی‌شود؛ فایل خراب مانع بررسی بقیهٔ کتاب‌ها نمی‌شود. فرمت‌هایی مثل EPUB/DJVU فقط در فهرست می‌آیند و استخراج آن‌ها در این نسخه انجام نمی‌شود. وضعیت `extraction_complete` فقط موفقیت فنی استخراج متن است و به‌معنی صحت متن یا اعتبار علمی نیست.

## اجرای دستی و محدودیت‌ها

```bat
py -3 -m venv .venv-books
.venv-books\Scripts\python.exe -m pip install -r backend\requirements-books.txt
.venv-books\Scripts\python.exe backend\tools\local_orthopedic_library.py --source "D:\orthopedic book"
```

برای تعیین محل خروجی و سقف‌های متفاوت:

```bat
.venv-books\Scripts\python.exe backend\tools\local_orthopedic_library.py --source "D:\orthopedic book" --output "D:\4B-private-library" --max-file-mib 2048 --max-pages 12000
```

خروجی باید بیرون پوشهٔ کتاب‌ها و بیرون مخزن عمومی بماند. مقدار پیش‌فرض سقف هر فایل ۱۰۲۴ MiB و هر PDF ده‌هزار صفحه است؛ عبور از سقف صریح گزارش می‌شود. کد خروج صفر یعنی استخراج کامل، یک یعنی مورد نیازمند بررسی یا کتابی پیدا نشده، و دو یعنی اجرا شروع نشده است.

## ادامهٔ تحلیل در همان رایانه

در Codex محلی، مخزن پروژه و مسیر گزارش را در دسترس قرار دهید و این دستور را بدهید:

> کتاب‌های اصلی را فقط بخوان و تغییر نده. مخزن 4B-MOS و پوشهٔ D:\orthopedic book را بررسی کن. اگر manifest محلی نداریم، ابزار backend/tools/local_orthopedic_library.py را طبق راهنمای پروژه اجرا کن. عنوان، ویرایش، سال و تطبیق شمارهٔ چاپی صفحه را از خود کتاب تأیید کن. صفحه‌های ناقص، OCR نشده و رمزدار را جدا گزارش کن. از فصل‌های زانو شروع کن: OA، منیسک، غضروف/استئوکندرال، شرح‌حال و معاینه. گزاره‌ها را با بیان مستقل، جمعیت، شرایط کاربرد، محدودیت، نام کتاب/ویرایش، فصل/صفحهٔ تأییدشده، هش PDF و هش متن صفحه استخراج کن. اختلاف با راهنماهای به‌روز را ثبت کن. از Registry و قراردادهای موجود استفاده کن؛ همهٔ گزاره‌های جدید Draft بمانند و تا بررسی مستقل متخصص Approved نشوند. متن کامل، صفحات، تصاویر یا corpus کتاب را به GitHub عمومی نفرست. پایگاه بیماران، migration عملیاتی، فعال‌سازی قواعد ایمنی و merge main انجام نده.

این ابزار مرحلهٔ آماده‌سازی منبع است: در اجرای آن **صفر گزارهٔ Draft و صفر Approved** ساخته می‌شود. ثبت گزارهٔ پزشکی، تحلیل علمی و اتصال به Registry مراحل بعدیِ صریح و قابل‌بازبینی هستند. این نشست ابری تاکنون هیچ‌یک از کتاب‌های واقعی هارد شما را دریافت یا مطالعه نکرده است.

## آزمون انجام‌شدنی

```bash
python -m pip install -r backend/requirements.txt -r backend/requirements-dev.txt -r backend/requirements-books.txt
python -m pytest backend/tests/test_local_orthopedic_library.py backend/tests/test_local_orthopedic_library_review.py -q
```

تست‌ها فقط PDF ساختگی تولید می‌کنند. اجرای واقعی CMD روی Windows و خواندن کتاب‌های واقعی نیازمند رایانهٔ کاربر است؛ نتیجهٔ تست Linux یا CI به‌معنی انجام این دو کار نیست.
