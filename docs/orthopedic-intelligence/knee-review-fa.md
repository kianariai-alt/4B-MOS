# پیش‌نویس بازبینی مسیر زانو

این خروجی یک سند طراحی آفلاین است: ۹ مرحله و ۲۶ جایگاه مفهومی برای بازبینی پزشک. همهٔ جایگاه‌ها `draft` و غیرفعال‌اند؛ سؤال بیمار، شرط نمایش، آستانه، تشخیص، توصیه درمان یا قاعدهٔ اجرایی از آن‌ها تولید نمی‌شود. معتبر بودن ساختار JSON فقط نتیجهٔ بررسی نرم‌افزاری سند است.

بستهٔ اصلی `4B-Knee-Decision-Design-v1.zip` در این محیط موجود نبود. [فایل JSON](knee-review-draft.json) از **خلاصهٔ تحویل کاربر** بازسازی شده است؛ فایل اصلی بازیابی نشده و تطبیق گره‌به‌گره آن معلوم نیست. عدد ۲۶ نشانهٔ تطبیق با اصل یا تأیید علمی نیست. متن کامل روش ویزیت پزشک نیز هنوز دریافت نشده است.

## محتوای قابل بازبینی

| مرحلهٔ طراحی | جایگاه‌ها | موضوع بازبینی |
| --- | --- | --- |
| ورود و مرز کاربرد | R01–R02 | شکایت زانوی بزرگسال و مسیرهای کامل‌نشده |
| رسیدگی فوری | R03–R05 | جایگاه بررسی علائم، پاسخ نامعلوم مستقل و مسئول تصمیم |
| شرح‌حال | R06–R08 | شکایت و سیر، درد و عملکرد، سوابق و داروها |
| مسیرهای موازی | R09–R11 | آسیب حاد، الگوی تدریجی و سایر علل یا نامشخص |
| معاینه و تصویربرداری | R12–R14 | یافتهٔ تأییدشده، بررسی هدفمند و حدود راهنمای منیسک |
| ایمنی مشترک | R15–R17 | بیماری زمینه‌ای، بازبینی دارویی کلیه و دادهٔ ناقص |
| مقایسهٔ گزینه‌ها | R18–R21 | توان‌بخشی، دارو، تزریق و ارزیابی جراحی برای بررسی پزشک |
| تصمیم و بازبینی | R22–R24 | اختیار پزشک اصلی، هدف و زمان بازبینی |
| پیگیری | R25–R26 | ثبت پیامد و عارضه با منشأ و زمان |

شناسهٔ کامل جایگاه‌ها `KNEE-R01` تا `KNEE-R26` است. ترتیب مرحله‌ها جایگزین مسیر اجرایی پرسش‌نامه نیست. سه مسیر R09، R10 و R11 می‌توانند هم‌زمان مطرح باشند؛ هیچ‌کدام انتخاب اجباری یک تشخیص نیست.

برای هر جایگاه، نسخه، منشأ بازسازی، هدف بازبینی و منابع پیشنهادی ثبت شده‌اند؛ `clinical_question`، `answer_schema`، `display_condition` و `medical_rule` عمداً `null` هستند. محدودیت‌های علمی تحویل کاربر نیز با منشأ «نیازمند بازبینی مستقل» نگه داشته شده‌اند. از جمله: دامنهٔ محدود منیسک حاد منفرد، نبود MRI خودکار، تفاوت PRP با PL و PRGF، تفاوت شواهد حیوانی و انسانی اگزوزوم، نبود ادعای تأییدشده برای هم‌افزایی ACS+PL+EXO و جداسازی Bio Harmony از شواهد علمی. مرز پیشنهادی توقف پیشنهاد خودکار NSAID خوراکی در بیماری کلیوی نیز **فقط موضوع بازبینی** است و این سند آن را اجرا نمی‌کند.

صفحه، بخش و نسخهٔ دقیق منابع در این بازبینی مستقل تأیید نشده‌اند و `null` مانده‌اند. لینک منبع به معنی تأیید پشتوانهٔ یک گزاره یا مجوز کپی و نمایه‌سازی تجاری نیست. برای اعتبارسنجی فایل‌های پژوهشی از [فهرست و ابزار منابع](research-sources-fa.md) استفاده شود؛ ابزار این سند فایل مقاله یا مجوز آن را بررسی نمی‌کند.

## نمایش آفلاین و بررسی ساختار

ابزار فقط به کتابخانهٔ استاندارد Python نیاز دارد؛ برنامه، تنظیمات `.env`، دیتابیس، Registry، موتور مصاحبه یا شبکه را بارگیری نمی‌کند. از ریشهٔ پروژه در Windows:

```powershell
.venv\Scripts\python.exe -m backend.tools.review_knee_draft --format json
.venv\Scripts\python.exe -m backend.tools.review_knee_draft --html scratch/knee-review.html
Start-Process scratch/knee-review.html
```

در محیط‌های دیگر می‌توان به‌جای `.venv\Scripts\python.exe` از `python` استفاده کرد. فایل HTML مستقل است و برای نمایش به اینترنت نیاز ندارد؛ لینک منبع فقط با انتخاب خواننده باز می‌شود. خروجی پیش‌فرض در مخزن نوشته نمی‌شود؛ مسیر `--html` را خود اجراکننده تعیین می‌کند.

ابزار فیلد اضافه، فعال‌سازی، وضعیت تأییدشده، جایگاه تکراری یا گمشده، ارجاع ناشناخته و ادعای بازیابی فایل اصلی را رد می‌کند. در این نسخه، افزودن سؤال یا شرط اجرایی نیز خطاست؛ بعد از دریافت متن پزشک باید در قرارداد مصاحبه و گردش تأیید موجود توسعه داده شود. ابزار تأیید نمی‌کند که یک متن پزشکی صحیح است یا یک صفحهٔ منبع از آن پشتیبانی می‌کند.

تست مستقل بدون نصب وابستگی‌های برنامه:

```powershell
.venv\Scripts\python.exe -m unittest backend.tests.test_knee_review_draft -v
```

## هماهنگی با کارهای موازی

در بررسی ۲۲ اکتبر ۲۰۲۶، [PR #47](https://github.com/kianariai-alt/4B-MOS/pull/47) با head `83e041633929e5779800721d5cb22ee932678971` باز و draft بود. آن مسیر، بستهٔ تألیف دانش زانو، سؤال‌های پیشنهادی و `OrthopedicDecisionKnowledge 1.0.0` را با استفاده از Registry و `BankContent` موجود توسعه داده است. این سند جایگزین آن بسته نیست و گزاره‌ها، سؤال‌ها، import یا موتور آن را دوباره پیاده نمی‌کند. تعداد ۲۶ جایگاه این سند با ۲۷ گزاره یا ۲۲ سؤال آن PR هم‌ارز نیست؛ هیچ نگاشت خودکار وجود ندارد.

[PR #44](https://github.com/kianariai-alt/4B-MOS/pull/44)، head `8129085ffea310a62778fa2c8b87f47a198d0956`، قرارداد سخت‌گیرانهٔ یکپارچه‌سازی و snapshot بالینی دارد. پاسخ بیمار، این سند طراحی و خروجی Draft ارتوپدی، منبع final یا `KnowledgeReference` تأییدشدهٔ آن محسوب نمی‌شوند. `state=confirmed` در پیش‌نمایش ارتوپدی نیز به معنی تأیید سروری پزشک نیست و هش زمینهٔ حداقلی آن با هش پروندهٔ نهایی یکپارچه‌سازی تفاوت دارد.

[PR #49](https://github.com/kianariai-alt/4B-MOS/pull/49)، head `7645347f9690b7c2b4703c0f3dc6d579494744b0`، روی شاخهٔ #44 قرار دارد و آزمون اتصال تولیدکنندگان ثابت‌شده را انجام می‌دهد؛ نسخهٔ ارتوپدی آزموده‌شدهٔ آن `7e41e079de4cb021c45ade9cf0abc2f8aa8a5499` است. این نتیجه به‌تنهایی سازگاری head جدید #47 را اثبات نمی‌کند. فایل‌های این خروجی با فایل‌های آن سه PR هم‌نام نیستند و هیچ‌یک وارد یا ادغام نشده‌اند.

## ورودی لازم برای حرکت به مصاحبهٔ واقعی

متن کامل روش ویزیت و سؤال‌های پزشک باید دریافت شود؛ سپس نوع پاسخ، واحد و محدوده، شرط‌های نمایش، رفتار unknown و declined، بازبینی پاسخ و قواعد خروج از مسیر تعیین می‌شوند. متن علمی، تریاژ، پیشنهاد درمان و زمان پیگیری نیازمند بازبینی مسئول بالینی و ارجاع دقیق منبع هستند. شاخهٔ کامل تروما، ACL، کودکان، زانوی پروتزی و جراحی اخیر همچنان آماده نیست. این خروجی چیزی در برنامه ثبت، منتشر یا فعال نمی‌کند.
