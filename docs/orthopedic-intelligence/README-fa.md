## توان و شکاف نسخهٔ مبنا

مصاحبهٔ موجود از بانک اختصاصی پزشک با ثبت رویداد، SHA256، پیش‌نویس، تأیید صریح همان نسخه و بازنشستگی استفاده می‌کرد. نسخهٔ مبنا پاسخ متن، بله/خیر و گزینهٔ واحد، وضعیت unknown/declined، یک شرط وابسته به پاسخ سؤال قبلی، قفل نوشتن، expected_version و تکرار ایمن درخواست را داشت. پاسخ عددی، شرط ترکیبی، ویرایش پاسخ قبلی و تاریخچهٔ ابطال مسیر در آن نبود.

Registry موجود چرخهٔ `draft → in_review → approved/rejected → retired` و نسخهٔ جانشین دارد. نویسنده و ویرایشگر همان نسخه نمی‌توانند بازبین مستقل آن باشند. گزارهٔ تأییدشده از API ویرایش نمی‌شود؛ جانشین تا تأیید، draft می‌ماند. مشخصات گزاره شامل جمعیت، اندیکاسیون، منع مصرف، سطح شواهد و اعتبار زمانی است. مصرف‌کننده فقط approved معتبر را می‌خواند.

مشخصات فعلی منبع، URL، DOI، ناشر، نسخهٔ راهنما، publication_date و accessed_at دارد؛ مجوز استفاده، صفحه/بخش، فایل آفلاین و SHA256 آن، تاریخ بررسی منبع و تفکیک سیاست تجاری هنوز فیلد اختصاصی ندارند. فهرست پژوهشی این تحویل این اطلاعات و کمبودهایشان را جدا نگه می‌دارد و به Registry فعال وارد نمی‌کند.

Clinical Context از شرح‌حال و گزارش final جاری استفاده می‌کند؛ observation ساختاریافته از quantity با واحد، integer، boolean، coded، datetime و absent پشتیبانی می‌کند. صفر درد از None متمایز است. پاسخ بیمار بدون مرور پزشک به این یافته‌ها تبدیل نمی‌شود.

تصمیم‌یار موجود شامل قواعد ایمنی قطعی، خلاصهٔ شواهد با انتخاب پزشک، Physician Copilot و نقشه‌راه مبتنی بر پیامد محلی است. قواعد ایمنی فعلی قرارداد شرط مستقل خود را دارند و برای unknown پرسش‌نامه استفاده نشده‌اند. نقشه‌راه فقط با دادهٔ واقعی واجد شرایط، از جمله حداقل پنج بیمار مستقل برای cohort مربوط، نمایش داده می‌شود؛ دادهٔ ساختگی برای حذف پیام نبود نقشه‌راه اضافه نشده است.

## خروجی قابل اجرا

- پرسش عددی با واحد و حداقل/حداکثر، شرط‌های ترکیبی all/any و مسیر صریح unknown/declined در موتور موجود.
- اصلاح پاسخ فعال قبلی از همان endpoint با حفظ رویدادهای رمزگذاری‌شده و حذف پاسخ‌های نامرتبط از مسیر فعال؛ بازگشت به مسیر قدیمی پاسخ ابطال‌شده را خودکار برنمی‌گرداند.
- خلاصهٔ فارسی و ساختاریافتهٔ پزشکیار در `interview.assistant_summary` با نسخهٔ قرارداد، بانک، پزشک، منشأ و وضعیت هر پاسخ؛ فقط خوداظهاری بیمار.
- رابط عددی و مرور/اصلاح پاسخ در پورتال و نمایش خلاصه در صندوق و کنار فرم شرح‌حال.
- [قرارداد مصاحبه](interview-contract-fa.md)، [JSON Schema](interview-contract-v1.schema.json)، فهرست منابع پژوهشی غیرفعال و [پیش‌نویس مرور زانو](knee-review-fa.md).

از ریشهٔ پروژه می‌توان بدون اتصال به دیتابیس، قرارداد را صادر و پیش‌نویس زانو را به HTML آفلاین تبدیل کرد:

```powershell
.venv\Scripts\python.exe -m backend.tools.export_interview_contract --output docs/orthopedic-intelligence/interview-contract-v1.schema.json
.venv\Scripts\python.exe -m backend.tools.review_knee_draft --help
.venv\Scripts\python.exe -m backend.tools.validate_orthopedic_research --help
```

دستورهای دقیق مرور زانو و اعتبارسنجی منابع در راهنمای همان خروجی آمده‌اند. هیچ‌یک به فعال‌سازی در دیتابیس منجر نمی‌شود. تست‌ها از ریشه اجرا می‌شوند:

```powershell
.venv\Scripts\python.exe -m pytest backend/tests -q
node backend/tests/patient_portal_ui_qa.cjs
```

برای تست رابط ابتدا وابستگی‌های `backend/tests/ui` مطابق CI نصب می‌شوند و `MOS_UI_QA_MODULES` به node_modules همان پوشه اشاره می‌کند. بررسی syntax با `node --check` به jsdom نیاز ندارد. هیچ وابستگی جدیدِ زمان اجرا یا مدل سنگین به برنامه اضافه نشده است.

## نصب کلینیک و موارد باز

این محیط به PC کلینیک، PostgreSQL محلی یا .env آن متصل نیست. READY نصب قبلی را نمی‌توان از تست نرم‌افزار نتیجه گرفت. revision مورد انتظار main فعلی `a1d4e7f0b386` است و این تغییر migration ندارد. بررسی امن روی PC، از `C:\Users\4B\4B-MOS`:

```powershell
.venv\Scripts\python.exe -m backend.tools.release_preflight --format json
```

دستور فقط کدهای وضعیت ثابت را گزارش می‌کند؛ رمز، URL دیتابیس و اطلاعات بیمار چاپ نمی‌شود. برای اعمال نسخه، پس از ادغام و با همان روال پشتیبان‌گیری و نصب مستند کلینیک عمل شود؛ این تحویل اجرای راه‌دور روی Windows را ادعا نمی‌کند. AUDIO_PIPELINE_ENABLED تغییر داده نشده است.

برای مرحلهٔ بعد نیاز است: متن کامل روش ویزیت و پرسش‌های پزشک، بازبینی متن و شروط و واحد/محدودهٔ هر پرسش، تکمیل صفحه/بخش و مجوز منابع، و آزمون بالینی مستقل. شاخه‌های کامل تروما، ACL، کودکان، زانوی پروتزی و جراحی اخیر هنوز آماده نیستند. OTP، حساب دائمی بیمار، چندکلینیکی، اشتراک میان متخصصان و ظرفیت مدل آفلاین نیز با این تغییر پیاده‌سازی نشده‌اند.
