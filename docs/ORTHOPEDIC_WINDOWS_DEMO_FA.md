# نسخهٔ آزمایشی آفلاین زانو برای ویندوز

این بسته برای دیدن و امتحان‌کردن درخت ۳۰ سؤالی زانو و مرور ده پروندهٔ ساختگی آماده شده است. پس از دریافت فایل، در Edge یا Chrome و بدون اینترنت اجرا می‌شود. نصب Python، PowerShell، دیتابیس، برنامهٔ دیگر یا دسترسی Administrator لازم نیست.

تمام محتوای پزشکی و نگاشت منابع **Draft و نیازمند بررسی مستقل متخصص** است. این نسخه برای بازبینی فرم و رفتار پیش‌نمایش است؛ تشخیص، احتمال بیماری، انتخاب درمان یا تأیید ایمنی بیمار ارائه نمی‌کند. فقط اطلاعات ساختگی وارد کنید.

## اجرا در سه قدم

۱. فایل `4B-MOS-Windows-Demo.zip` را دریافت کنید.

۲. روی ZIP راست‌کلیک کنید و **Extract All / استخراج همه** را بزنید. سپس پوشهٔ استخراج‌شدهٔ `4B-MOS-Windows-Demo` را باز کنید.

۳. روی `Run-4B-MOS-Demo.cmd` دوبار کلیک کنید. این فایل فقط صفحهٔ آزمایش را در مرورگر پیش‌فرض باز می‌کند. همچنین می‌توانید مستقیماً `4B-MOS-Windows-Demo.html` را با Edge یا Chrome باز کنید.

برای دریافت تک‌فایل، خود `4B-MOS-Windows-Demo.html` نیز کافی است. صفحه به پوشهٔ کامل پروژه، کتاب‌ها یا برنامهٔ نصب‌شده متکی نیست. اگر ویندوز اجرای فایل CMD را محدود کرد، همان فایل HTML را مستقیماً در مرورگر باز کنید.

## دو بخش متفاوت در برنامه

| بخش | چه چیزی را نشان می‌دهد؟ | چه چیزی را می‌توان امتحان کرد؟ |
|---|---|---|
| پرونده‌های ساختگی | خروجی واقعی موتور Python برای ده ورودی ثابت، تولیدشده در زمان ساخت بسته | انتخاب پرونده، مشاهدهٔ سؤال‌های پیشنهادی، ابهام‌ها و ارجاع‌های همان خروجی |
| فرم آزمایشی | فرم قابل‌ویرایش ۳۰ سؤالی و نمایش شاخه‌ها براساس شرایط صریح درخت | پاسخ‌دادن به سؤال‌ها، باز و بسته‌شدن شاخه‌ها، سابقه‌های درمان جدا و مرور پاسخ‌های واردشده |

**ویرایش فرم، اجرای زندهٔ موتور Python نیست.** جمع‌بندی فرم فقط پاسخ‌های واردشده را برای مرور نمایش می‌دهد؛ تحلیل بالینی یا خروجی موتور برای پروندهٔ تازه تولید نمی‌کند. خروجی موتور فقط در بخش پرونده‌های ساختگی و برای همان ورودی ثابت قابل‌مشاهده است.

## پیشنهاد برای اولین آزمایش

- ابتدا یک پروندهٔ ساختگی را انتخاب کنید و سؤال‌های پیشنهادی و منابع آن را ببینید. سپس پروندهٔ آسیب ورزشی و پروندهٔ شرح‌حال ناقص را با آن مقایسه کنید.
- وارد فرم آزمایشی شوید. وجود یا نبود درد را صریحاً مشخص کنید؛ انتخاب «تورم» به‌عنوان شکایت اصلی، نبود درد را ثابت نمی‌کند.
- پاسخ آسیب را از «خیر» به «بله» تغییر دهید و شاخهٔ سؤال‌های وابسته را ببینید. «نمی‌دانم» با «خیر» یکسان نیست.
- اگر درمان قبلی را مثبت ثبت کردید، دو سابقهٔ درمان جدا بسازید و تغییر درد و تغییر عملکرد هرکدام را مستقل وارد کنید.
- برای شروع دوباره از دکمهٔ بازنشانی استفاده کنید. شمارهٔ سؤال و اصلاح پیشنهادی‌تان را در همین گفت‌وگو بفرستید.

پاسخ‌های شاخه‌ای که بعداً بسته می‌شود ممکن است برای امکان اصلاح در حافظهٔ همان صفحه حفظ شوند؛ این داده‌ها نباید پاسخ قابل‌استفادهٔ شاخهٔ فعال تلقی شوند. ثبت «هر دو زانو» نیز جای شرح‌حال جدا برای سمت راست و چپ را نمی‌گیرد.

## داده و منابع

برنامه پاسخ‌ها را خودکار به فایل، کوکی یا فضای ذخیره‌سازی پایدار مرورگر نمی‌نویسد و درخواست شبکه یا ارسال داده ندارد. پاسخ‌های آزمایشی در حافظهٔ همان صفحه‌اند و با بازنشانی پاک می‌شوند؛ فایل HTML اصلی با واردکردن پاسخ تغییر نمی‌کند. بسته به دیتابیس، GitHub، پروندهٔ بیمار یا درایو `D:` متصل نمی‌شود.

متن یا تصویر کتاب‌ها در بسته نیست. آنچه برای مرور منبع نمایش داده می‌شود، متن کوتاهِ تألیفی سؤال‌ها و گزاره‌ها، مشخصات ارجاع و هش‌های نسخه است. دامنهٔ بررسی کتابیِ قبلی ۳۷ صفحهٔ منتخب و مجاور بوده است؛ تأیید بصری اصل PDF و بررسی مستقل پزشکی همچنان لازم‌اند. اتصال مستقیم کتابی سؤال‌های درد، عملکرد و بیماری همراه، محدود به زمینهٔ بازبینی آرتروپلاستی است و پرسشنامهٔ اعتبارسنجی‌شده محسوب نمی‌شود.

## مرز این نسخه و وضعیت آزمون

این بسته یک پیش‌نمایش آفلاین برای بازبینی است. پیش‌نمایش‌های قبلی، قرارداد مشترک Integration، Registry و قواعد عملیاتی ایمنی را تغییر نمی‌دهد. استفاده از سامانهٔ کامل، ورود به پروندهٔ واقعی و اتصال عملیاتی به Copilot موضوع جداگانه‌ای است.

ساخت فایل HTML یا موفقیت آزمون‌های Linux به‌تنهایی شاهد اجرای آن در ویندوز نیست. وضعیت واقعی آزمون رابط، بسته‌بندی و اجرای Windows باید همراه Commit و CI همان تحویل گزارش شود. تأیید متن سؤال توسط کاربر و موفقیت تست نرم‌افزار، تأیید مستقل پزشکی نیستند.

برای توسعه‌دهنده، دادهٔ پرونده‌های نمونه از همان [درخت پیش‌نمایش موجود](ORTHOPEDIC_INTERVIEW_TREE_FA.md) و خروجی سرویس Python آن گرفته می‌شود؛ منطق عمومی تصمیم‌گیری تازه‌ای در مرورگر ساخته نمی‌شود. ساخت و بازتولید بسته باید با ابزار بسته‌بندی همین مخزن انجام شود و نتیجهٔ آن در گزارش تحویل ثبت شود.
