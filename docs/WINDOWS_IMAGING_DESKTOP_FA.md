# نمایشگر محلی MRI و CT برای ویندوز

این برنامه مستقل، شاخه `feature/windows-imaging-viewer`، بر مبنای نسخهٔ
`1717a95a984556f72cb08fdcefe84c2514c28e29` از PR۵۱ است. پنجرهٔ واقعی Qt و
رندر حجمی VTK دارد؛ برای اجرا به FastAPI، PostgreSQL، مرورگر یا سرویس ابری
نیاز ندارد. ماژول دانش، Decision Validation و قواعد Clinical Safety تغییر نکرده‌اند.
نمایشگر هیچ یافته‌ای را به پرونده یا Physician Copilot ثبت نمی‌کند.

## استفاده در ویندوز

روش پیشنهادی، بستهٔ `4B-Imaging-Windows-Installer-x64` است: فایل
`4B-Imaging-Setup-x64.exe` را اجرا کنید. نصاب خودکفا تمام payload را همراه
دارد و بدون نیاز به Administrator در پوشهٔ برنامه‌های همین کاربر نصب می‌کند.
سپس برنامه از منوی Start اجرا می‌شود؛ حذف آن از Settings → Apps ممکن است.
نصب‌کننده هیچ دادهٔ بیمار، دیتابیس یا Migration را دریافت یا اجرا نمی‌کند.

بستهٔ `4B-Imaging-Windows-x64` از workflow همین PR را کامل استخراج کنید و
`4B-Imaging.exe` را اجرا کنید. پوشهٔ `_internal` باید کنار فایل اجرایی بماند.
نصب Python روی رایانهٔ کاربر نهایی لازم نیست. این یک بستهٔ پژوهشی portable،
بدون امضای دیجیتال است؛ Windows 10/11 x64، حداقل ۸ گیگابایت RAM و درایور
گرافیک OpenGL 3.2 لازم دارد. بسته‌های CI چهارده روز نگه داشته می‌شوند.

### خطای Failed to load Python DLL

بستهٔ portable را از داخل پنجرهٔ ZIP اجرا نکنید. Explorer ممکن است فقط exe
را در `Temp` کپی کند و `_internal/python312.dll` همراهش نباشد؛ خطا قبل از
رسیدن اجرا به کد Python/GUI رخ می‌دهد. روی ZIP گزینهٔ **Extract All** را بزنید
و از پوشهٔ استخراج‌شده اجرا کنید، یا نسخهٔ Setup را نصب کنید. exe و `_internal`
باید کنار هم باشند. نیازی به نصب Python جداگانه نیست.

اگر در پوشهٔ کامل DLL وجود دارد ولی باز هم LoadLibrary خطا می‌دهد، نبودن
وابستگی بومی یا محدودیت سیستم باید با پیام و نسخهٔ ویندوز بررسی شود؛ عکس به‌تنهایی
وجود همهٔ DLLهای وابسته را ثابت نمی‌کند. فایل DLL از منابع نامعتبر جایگزین نشود.

۱. «نمونهٔ ساختگی» مسیر کامل ساخت DICOM تا نمایش را بدون دادهٔ بیمار اجرا می‌کند.
۲. برای دادهٔ خود، پوشهٔ DICOM، ZIP یا لینک مستقیم HTTPS دانلود DICOM/ZIP را باز کنید. برای **صفحهٔ رمزدار مرکز**، لینک HTTPS را وارد و «ورود به صفحهٔ مرکز» را بزنید. کد و رمز را در صفحهٔ خود مرکز وارد کنید؛ انتخاب دانلود DICOM/ZIP در همان پنجره، فایل را به پردازشگر منتقل می‌کند.
۳. اگر چند سری وجود دارد، سری را از فهرست انتخاب کنید. سری‌ها و Studyهای متفاوت با هم ادغام نمی‌شوند.
۴. ماوس چپ حجم را می‌چرخاند؛ ماوس میانی جابه‌جا می‌کند؛ چرخ ماوس بزرگ‌نمایی می‌کند.
۵. «چرخش خودکار» دوربین را حرکت می‌دهد. «پخش برش‌ها» index مقطع k را تغییر می‌دهد.
۶. آستانه، تراکم نمایش، window/level، رنگ کاذب شدت و صفحهٔ برش قابل تنظیم‌اند.
۷. کلیک در مقطع، نقطهٔ مشترک را با affine در حجم مشخص می‌کند. نسبت فیزیکی پیکسل‌ها حفظ می‌شود.

این دو نوع حرکت، دوربین و پیمایش مقطع هستند؛ انیمیشن تغییر شکل مفصل، حرکت
فیزیولوژیک زانو یا ثبت زمانی dynamic MRI انجام نشده است.

## نوع لینک و احراز هویت

دو مسیر مستقل وجود دارد: «دریافت و بازکردن» برای لینک مستقیم داده است؛ «ورود به صفحهٔ مرکز» یک مرورگر خصوصی QtWebEngine برای صفحهٔ رمزدار باز می‌کند. کد/رمز را خود کاربر در صفحه وارد می‌کند. profile بدون نام، off-the-record، با cache حافظه‌ای و بدون cookie دائمی است؛ خطای گواهی پذیرفته نمی‌شود و دسترسی‌های دوربین/میکروفن/clipboard و فایل محلی داده نمی‌شود. صفحه می‌تواند مانند مرورگر معمولی به مرکز و وابستگی‌های خودش وصل شود؛ اطلاعات ورود به سرور 4B ارسال نمی‌شود.

پس از انتخاب دانلود DICOM/ZIP در پورتال، درخواست مرورگر در پوشهٔ موقت اختصاصی همین رایانه با نام ثابت غیرهویتی دریافت، به importer منتقل و پس از snapshot خواندن حذف می‌شود. نام فایل پیشنهادشدهٔ مرکز استفاده نمی‌شود. لغو/قطع دانلود وارد بازسازی نمی‌شود. برای جلوگیری از اختلال فایل‌های در حال پردازش، هم‌زمان یک دانلود پذیرفته می‌شود.

صفحهٔ HTML، عکس JPEG و فیلم دادهٔ حجمی DICOM نیستند. مسیر مستقیم، HTML/JSON را رد می‌کند. مرورگر پورتال برای انتخاب دانلود است؛ پیکسل‌های viewport یا screenshot را به حجم تبدیل نمی‌کند. ورود خودکار، شکستن CAPTCHA، scraping و استخراج عمومی WADO از همهٔ PACSها پیاده نشده‌اند. اگر پورتال گزینهٔ دانلود DICOM ندارد، به adapter متناسب با API و احراز هویت همان سامانه نیاز است. سازگاری با مرکز واقعی در این مرحله آزموده نشده است.

توکن Bearer اختیاری فقط برای همان دانلود استفاده می‌شود. رمز ورود مرکز را
در این فیلد قرار ندهید. HTTPS با کنترل گواهی و hostname الزامی است؛ گزینه‌ای
برای خاموش‌کردن TLS وجود ندارد. ریدایرکت فقط در همان hostname/port پذیرفته
می‌شود تا توکن به مقصد دیگری نرود. برای لینک CDN متفاوت، نشانی نهایی دانلود
را دریافت کنید. دانلود سقف حجم، timeout اتصال، مهلت کلی و لغو دارد.
«لغو» ممکن است تا پایان read جاری شبکه، حداکثر timeout پانزده‌ثانیه‌ای، منتظر بماند.

هیچ لینک واقعی مرکز یا فایل واقعی بیمار در توسعه/CI دریافت نمی‌شود. آزمون
شبکه با HTTPS واقعی loopback، گواهی موقت معتبر برای localhost و DICOM تولیدشده است.

## مرز پردازش واقعی و ظاهر آناتومیک

مسیر pixel جدید مستقل از `SyntheticVolumeReconstructor` است و marker دادهٔ
ساختگی نمی‌خواهد. متادیتای allowlistشده از snapshot بایتی خوانده و با
`SeriesMetadataReader` و `StudySeriesValidator` موجود کنترل می‌شود. همان
snapshot برای pixel decode مصرف می‌شود. نام بیمار، PatientID، تاریخ‌ها،
SeriesDescription و private tagها خوانده یا در UI چاپ نمی‌شوند.

برش‌ها از position و orientation مرتب می‌شوند؛ affine مرکز voxel، i/j/k را
به LPS میلی‌متر می‌برد. فاصلهٔ برش از position به دست می‌آید. مقاطع نمایشگر
صفحات شبکهٔ ورودی‌اند؛ برای سری oblique ادعای reslice بیمارمحور ندارند.
محورهای جهت و مکان حجم VTK با همان affine اعمال می‌شوند. CT signed،
MONOCHROME1/2 و rescale پشتیبانی می‌شوند. آرایهٔ مرجع immutable است.

حجم سه‌بعدی **از پیکسل‌های همان اسکن** ساخته می‌شود، ولی رنگ از تابع شدت
می‌آید. این رنگ، رنگ واقعی استخوان/رباط یا segmentation چندبافتی نیست.
در MRI شدت به sequence وابسته است؛ یک threshold عمومی نمی‌تواند غضروف،
منیسک و رباط را معتبر جدا کند. شکل بیمار از روی atlas جایگزین نمی‌شود.
رسیدن به نمای آناتومیک اختصاصی به segmentation چندسری، هم‌ترازی، اصلاح
متخصص و ارزیابی مستقل نیاز دارد. مدل عمومی PR۵۱ فقط در دکمهٔ نمونهٔ ساختگی استفاده می‌شود.

کامل‌بودن acquisition با فهرست همان فایل‌های دریافت‌شده اثبات نمی‌شود.
گزارش صریحاً `completeness=not_established` و `patient_identity_verified=false`
دارد. هیچ نتیجه تشخیصی یا تأیید ایمنی درمان صادر نمی‌شود.

## محدودیت پروفایل

- Part 10، classic single-frame CT/MR، خاکستری ۸ یا ۱۶ بیت؛ Explicit/Implicit VR Little Endian و Explicit VR Big Endian.
- فشرده‌سازی JPEG/JPEG-LS/JPEG2000/RLE، Enhanced multi-frame، RGB، گانتری tilt، grid نامنظم و reconstruction با resampling پشتیبانی نمی‌شوند.
- حداکثر ۵۱۲ فایل، هر DICOM حداکثر ۱۶ MiB، کل ورودی/ZIP حداکثر ۵۱۲ MiB و حجم انتخابی حداکثر ۶۴ میلیون voxel؛ طول هر بُعد حداکثر ۵۱۲.
- missing geometry، جهت/spacing ناسازگار، position تکراری، گپ قابل مشاهده، پیکسل ناقص و duplicate instance باعث توقف همان مسیر پردازش می‌شوند.
- ZIP روی دیسک extract نمی‌شود؛ traversal، symlink، رمزگذاری و سقف‌های uncompressed کنترل می‌شوند. PDFها و فایل‌های بدون Part 10 کنار گذاشته و شمرده می‌شوند.
- بازکردن منبع/سری جدید، تصویر و نقطهٔ منبع قبلی را پاک می‌کند؛ خطای منبع جدید، تصویر بیمار قبلی را باقی نمی‌گذارد.

دانلود مستقیم، داده و توکن در حافظهٔ همین فرایند نگه داشته می‌شوند. دانلود انتخابی از مرورگر پورتال، فایل موقت محلی دارد که پس از خواندن حذف می‌شود. برنامه تاریخچهٔ دائمی یا log حاوی URL و screenshot خودکار از ورودی واقعی نمی‌نویسد.
خطاها کد ثابت دارند. فایل‌های source فقط خوانده می‌شوند. این رفتار
ناشناس‌سازی یا تضمین پاک‌سازی RAM، swap، crash dump یا تاریخچهٔ سیستم‌عامل نیست.

## ساخت و آزمون

```powershell
# توسعه: از ریشه مخزن، با Python 3.12
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-imaging-desktop.txt
.\.venv\Scripts\python.exe -m backend.imaging_desktop
# ساخت exe در محیط مجزای windows/imaging/.venv
./windows/imaging/build.ps1
# اختیاری: ساخت نصب‌کننده با Inno Setup 6.3 یا جدیدتر
./windows/imaging/build-installer.ps1
# فقط دادهٔ ساختگی: آزمون ZIP استخراج‌شده، نصب و حذف
./windows/imaging/verify-package.ps1
```

```bash
python -m unittest discover -s backend/tests/imaging_desktop -v
python -m backend.imaging_desktop --self-test-core /tmp/imaging-self-test.json
# Linux + Mesa، فقط با دادهٔ ساختگی:
xvfb-run -a python -m backend.imaging_desktop --smoke-ui /tmp/desktop-ui
```

job ویندوز برنامه را روی Windows x64 با PyInstaller می‌سازد، تست‌های loader را
اجرا می‌کند و **خود فایل اجرایی بسته‌بندی‌شده** را با دادهٔ ساختگی آزمایش می‌کند.
همچنین ZIP را واقعاً استخراج و exe آن را در مسیری دارای فاصله اجرا می‌کند؛
تنها فایل Setup را به پوشه‌ای مجزا کپی می‌کند، نصب بدون تعامل را اجرا و
برنامهٔ نصب‌شده را با DICOM ساختگی آزمایش می‌کند؛ سپس حذف برنامه را می‌آزماید.
این آزمون، وابستگی نداشتن Setup به فایل‌های کنار آن و همراه‌بودن runtime در
بستهٔ تحویلی را بررسی می‌کند. گزارش و SHA نصب‌کننده همراه artifact منتشر می‌شود.
job Linux پنجره و pixel واقعی VTK، چرخش دوربین، cine، مقدار MPR، مکان LPS،
clipping، تغییر palette و پاک‌شدن تصویر قبلی پس از خطا را می‌آزماید. صفحهٔ ورود ساختگی در **QtWebEngine واقعی**، دانلود ZIP مرورگر، تحویل خودکار به importer و حذف فایل موقت نیز آزموده می‌شوند. TLS
واقعی، توکن، ریدایرکت و رد گواهی نامعتبر نیز جدا آزموده می‌شوند.
آزمون UI روی Windows با داده واقعی یا workstation بالینی انجام نشده است؛
درایور گرافیک رایانهٔ مقصد باید هنگام پذیرش بررسی شود.

بستهٔ portable فایل‌های shared Qt را نگه می‌دارد و اعلان‌های مجوز توزیع‌های
واقعی را در `licenses/` جمع می‌کند. منبع Qt/PySide و شرایط LGPL:
https://doc.qt.io/qtforpython-6/licenses.html . اعتبار الگوی نمونهٔ ساختگی
در `ANATOMY_ATTRIBUTION.md` همراه بسته موجود است.
