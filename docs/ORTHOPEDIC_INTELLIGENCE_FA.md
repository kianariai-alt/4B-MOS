# هسته دانش زانو و پرسشگری تطبیقی، نسخهٔ ۱

این نسخه یک خروجی فنی قابل‌آزمون برای **تألیف و بازبینی** است. گزاره‌ها، روابط، معاینات، پرسش‌ها و شواهد درمانی همگی Draft هستند. آزمون نرم‌افزار و مرور منابع در این تغییر، تأیید مستقل متخصص یا اعتبارسنجی بالینی نیست.

## مبنای توسعه و مرز مسئولیت

مبنای شاخهٔ `feature/orthopedic-intelligence`، main با Commit `bc6fb3f15825d6eaccaa45503ad61a432baf1c5b` است. [ممیزی مخزن](ORTHOPEDIC_REPOSITORY_AUDIT_FA.md) وضعیت واقعی شاخه‌های درخواست‌شده و PR شمارهٔ ۴۳ را ثبت می‌کند. کدهای ادغام‌نشدهٔ Foundation، Imaging و Integration وارد این تغییر نشده‌اند. هیچ migration یا وابستگی جدیدی اضافه نشده است.

پایگاه موجود PostgreSQL/SQLAlchemy و Registry برای نسخهٔ اول کافی‌اند: گزاره‌ها در Registry موجود، و روابط در یک بستهٔ تألیف JSON دارای Schema و هش نگهداری می‌شوند. پایگاه گرافی جدا لازم نیست. این بسته پایگاه موازی دانش تأییدشده نیست.

## ساختار و حاکمیت دانش

`backend/app/knowledge/knee_v1.json` شامل منابع واقعی، گزاره‌های OA، منیسک و غضروف/استئوکندرال، دانش هشدار، روابط مفاهیم، معاینات و شواهد درمانی است. برای هر گزاره شناسه، موضوع، ناحیه، جمعیت، شرایط کاربرد، محدودیت، منابع و نسخهٔ ۱ ثبت می‌شود. برای این نسخه `evidence_grade=ungraded` یعنی ارزیابی مستقل قطعیت شواهد انجام نشده؛ قدرت توصیهٔ خود راهنما در خلاصهٔ گزاره ثبت می‌شود و معادل درجهٔ قطعیت فرض نمی‌شود.

از `KnowledgeFactCreate` و `knowledge_content_digest` موجود استفاده می‌شود. محدودیت‌ها و شرایط ساختاریافتهٔ هر گزاره به‌صورت یک پیوست JSON خوانا در `statement` همان گزاره قرار دارند؛ بنابراین تغییر آن‌ها هش Registry را عوض می‌کند. هش هر گزاره و هش کل بسته هنگام بارگیری دوباره محاسبه می‌شوند. هش منبع در Adapter، هش **فرادادهٔ ارجاع** است؛ سند علمی یا PDF دانلودشده را تصدیق نمی‌کند. هش ارجاع گزاره، محتوای کامل قابل‌ثبت در Registry را پوشش می‌دهد و از خلاصهٔ کوتاه Adapter به‌تنهایی قابل‌بازمحاسبه نیست.

روابط، روش معاینه، افتراق‌ها، شواهد درمان و سیاست انتخاب سؤال وضعیت Draft و هش بسته/قواعد مستقل دارند. تأیید بعدی یک گزاره در Registry به‌معنای تأیید این اجزا نیست. هیچ نسخهٔ تأییدشده‌ای در این تغییر ادعا نمی‌شود. برای هر تغییر بستهٔ منتشرشده باید نسخه و هش جدید ایجاد و بازبینی شود؛ این انتشار اولیه قرارداد `1.0.0` است.

`import_knee_drafts(db, actor=...)` فقط با فراخوانی صریح توسعه‌دهنده از سرویس فعلی Registry رکورد Draft می‌سازد. در startup، API پیش‌نمایش یا اجرای demo فراخوانی نمی‌شود. پیش‌بررسی همهٔ کلیدها، وضعیت و هش موجود را کنترل می‌کند. اجرای مجدد فقط Draftهای دقیقاً یکسان را می‌پذیرد؛ نسخهٔ ویرایش‌شده، تأییدشده یا superseded تعارض ایجاد می‌کند. سرویس موجود هر گزاره را همراه audit آن commit می‌کند؛ واردسازی دسته‌ای اتمیک نیست و در شکست میانی باید پس از بررسی، همان Draftها را با اجرای مجدد ادامه داد. نشست باید فاقد تغییرات معلق باشد. هیچ واردسازی روی پایگاه واقعی در این مأموریت اجرا نشده است.

## منابع و محتوای پزشکی

[گزارش منابع](ORTHOPEDIC_SOURCES_REVIEW.md) و [منابع غضروف](ORTHOPEDIC_CARTILAGE_SOURCES.md) نسخهٔ واقعاً بررسی‌شده، DOI، تاریخ دسترسی و محدودیت هر منبع را مشخص می‌کنند. بررسی حاضر جست‌وجوی نظام‌مند یا تضمین پوشش تمام به‌روزرسانی‌ها تا امروز نیست. منابع با دسترسی محدود یا abstract-only صریح مشخص‌اند؛ جزئیات دسترس‌ناپذیر به قواعد تأییدشده تبدیل نشده‌اند.

در بسته، PRP و HA از نظر توصیهٔ راهنما، اثر پژوهشی و مقررات تفکیک شده‌اند. اختلاف AAOS و ACR دربارهٔ PRP حفظ می‌شود. ACS، PRGF، PL، Exosomes، SVF و MSC هر یک رکورد مستقل با ابهامات و وضعیت نامعلوم محصول/حوزهٔ مقرراتی دارند. اطلاعیهٔ FDA فقط با تاریخ و حوزهٔ آمریکا خوانده می‌شود؛ مجوز جاری یک محصول در ایران از آن استنتاج نمی‌شود. دادهٔ مشاهده‌ای کلینیک و خروجی مدل زبانی شواهد اثربخشی محسوب نمی‌شوند. انتخاب پروتکل، دوز، رتبه‌بندی درمان و ادعای بازسازی غضروف وجود ندارد.

Kellgren–Lawrence فقط درجه‌بندی رادیوگرافی است. درد و محدودیت عملکرد جدا ثبت می‌شوند؛ از درجهٔ KL تشخیص علائم، ناتوانی یا درمان انتخاب نمی‌شود. ضایعهٔ منیسک تروماتیک و دژنراتیو دامنهٔ شواهد یکسان ندارند. هیچ حساسیت، ویژگی، اثر درمان یا احتمال تشخیصی اختراع نشده است.

## پرسشگری و حفظ داده

انتخاب‌گر از `InterviewQuestion` و `BankContent` موجود استفاده می‌کند و بانک یا مخزن پاسخ جدیدی نمی‌سازد. ورودی فقط منطقه و پاسخ‌های کنترل‌شده با منشأ و وضعیت است؛ نام، شناسهٔ بیمار، تاریخ تولد و شرح‌حال آزاد پذیرفته نمی‌شوند. اطلاعات قبلی تغییر نمی‌کنند و هش زمینه، نسخهٔ قواعد، شناسهٔ قاعده و ارجاع گزاره برای هر پیشنهاد موجود است.

- پاسخ کامل و سازگار دوباره پرسیده نمی‌شود؛ پاسخ unknown/declined نیز خودکار تکرار نمی‌شود.
- پاسخ ناقص، ناسازگار یا unverified نیازمند روشن‌سازی پزشک می‌ماند؛ پاسخ قبلی حذف یا با آخرین مقدار جایگزین نمی‌شود.
- شرط سؤال فقط بر مقدار تایپ‌شدهٔ پاسخ معتبر والد اعمال می‌شود؛ مثلاً پرسش مکانیسم آسیب پس از تأیید گزارش آسیب.
- منشأ شرح‌حال، معاینهٔ پزشک و تصویربرداری جداست؛ یافتهٔ تصویری تأییدنشده یافتهٔ معتبر محسوب نمی‌شود.
- موضوع خارج از زانو یا ناحیهٔ نامشخص از افتراق‌های زانو خروجی نمی‌گیرد و برای روشن‌سازی ارجاع می‌شود.

محتوای قابل‌خروجی بانک صرفاً برای گردش Draft فعلی پزشک است؛ انتخاب‌گر آن را تأیید یا در مصاحبهٔ فعال وارد نمی‌کند. واژهٔ `confirmed` در ورودی پیش‌نمایش یعنی پاسخ ساختاریافتهٔ کامل از منشأ ذکرشده، نه تأیید سروری یک پروندهٔ بیمار. اتصال به پرونده در آینده باید منشأ و تأیید را از رکوردهای سرور احراز کند.

## Adapter و هماهنگی Integration

قرارداد افزایشی [orthopedic-decision-knowledge 1.0.0](contracts/orthopedic-decision-knowledge-1.0.0.schema.json) شامل حوزه، علائم، معاینه، یافتهٔ تصویری، شکاف‌ها، سؤال‌ها، ارجاعات افتراقی/علمی، نیازهای ارزیابی و هش‌هاست. ترتیب افتراق‌ها بر پایهٔ شناسه است؛ سازگاری بیمار با هر تشخیص `not_assessed` است. این نسخه فقط روابط دانشی را برای بررسی ارائه می‌دهد و درصد یا رتبهٔ تشخیص ندارد. نیاز ارزیابی به‌معنای دستور آزمایش یا تصویربرداری نیست.

قرارداد مشترک `CoreInput/CoreOutput 1.0.0` در شاخهٔ Integration تغییر نمی‌کند. Draftهای این بسته نمی‌توانند در فهرست approved-only آن به `KnowledgeReference` تبدیل شوند. اتصال بعدی باید با مسیر C هماهنگ شود: نگاشت وضعیت و منشأ رکوردهای نهایی، بررسی هش زمینه، کنترل دسترسی، تازگی snapshot و اتصال به Safety Engine. هیچ شبکهٔ بیزی، DecisionModelAdapter، مدل تصویرخوانی یا Orchestrator جدیدی ساخته نشده است. این PR همان محل رسمی بررسی قرارداد پیشنهادی با مسیرهای B و C است؛ پذیرش آن‌ها هنوز ادعا نمی‌شود.

## ایمنی و اجرا

دانش هشدار و سناریوهای مفصل دردناک و متورم، علائم سیستمیک و آسیب با علائم عروقی/عصبی فقط نیاز بررسی پزشک را در پیش‌نمایش آشکار می‌کنند. هیچ قاعدهٔ عملیاتی ثبت یا فعال نمی‌شود. Clinical Safety Rule Engine موجود مرجع اصلی است؛ `safety_evaluation=not_performed` و `is_clinical_clearance=false` در Adapter صریح‌اند. نبود علامت یا هشدار تأیید ایمنی نیست.

اجرای محلی از ریشهٔ مخزن:

```bash
python -m pip install -r backend/requirements.txt -r backend/requirements-dev.txt
python -m backend.tools.orthopedic_knowledge_demo
python -m pytest backend/tests/test_orthopedic_knowledge.py backend/tests/test_orthopedic_questions.py backend/tests/test_orthopedic_adapter.py -q
```

تولید مجدد Schemaها و خروجی ساختگی:

```bash
python -m backend.tools.orthopedic_knowledge_demo --write-artifacts
```

API فقط با `ORTHOPEDIC_PREVIEW_ENABLED=true` و احراز هویت `admin` یا `physician` فعال است و پاسخ `Cache-Control: no-store` دارد:

- `GET /api/v1/knowledge/orthopedics/knee`: بستهٔ Draft برای بازبینی.
- `POST /api/v1/knowledge/orthopedics/knee/preview`: پیش‌نمایش بدون ثبت داده؛ نمونهٔ ورودی `{"body_region":"knee","observations":[]}`.

این دو endpoint هیچ دسترسی به دادهٔ بیمار یا قواعد ایمنی برای ارزیابی بالینی ندارند. پیکربندی پیش‌فرض غیرفعال است. وضعیت اجرای واقعی تست، commit و CI در گزارش تحویل و PR ثبت می‌شود.
