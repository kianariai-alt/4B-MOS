# بازبینی شواهد پرونده و فاصله تا استدلال بالینی

ممیزی کد نشان می‌دهد نسخهٔ فعلی فقط دو الگوی علائمی و دو کارت یافتهٔ تصویری دارد. از ۳۰ سؤال، ۶ سؤال مستقیماً در تطبیق این الگوها نقش دارند؛ ۱۶ سؤال پیش‌نیاز، دامنه یا اطلاعات خطر را کنترل می‌کنند؛ سه سؤال فقط حضور سابقهٔ درمان را حفظ می‌کنند و پنج سؤال در خروجی assessment نقش ندارند. این شمارش، وابستگی نرم‌افزار است و معیار ارزش یا دقت بالینی سؤال‌ها نیست.

معاینهٔ ثبت‌شده در انتخاب الگوها مصرف نمی‌شود. متن‌های مؤید و محدودیت کارت‌ها عمدتاً از پیش نوشته شده‌اند. سابقهٔ آسیب می‌تواند باعث عدم تطبیق الگوی مزمن شود و سابقهٔ جراحی، حتی همراه توضیح بیمار، مسیر حل‌شده‌ای برای رفع توقف ندارد. این رفتارها نشان‌دهندهٔ محدودیت مدل‌اند؛ اثبات رد بیماری یا مشخص‌بودن تشخیص صحیح نیستند.

## اصلاح انجام‌شده در این مرحله

مسیر جداگانهٔ `build_knee_reasoning_review`، خروجی assessment موجود را بدون تغییر نگه می‌دارد و یک دفتر شواهد مبتنی بر ورودی می‌سازد:

- شرح مسئله از مقدار واقعی، وضعیت و منشأ پاسخ‌ها ساخته می‌شود؛ سن، یافتهٔ معاینه یا نتیجهٔ درمان ساخته نمی‌شود.
- داده‌های معتبر از داده‌های ناقص، متناقض و تأییدنشده جدا می‌مانند. متن آزاد عیناً حفظ می‌شود و به گزینهٔ کنترل‌شده یا تشخیص تبدیل نمی‌شود.
- برای هر چهار فرضیهٔ محدود مدل، وضعیت هر شرط و پاسخِ پشتیبان آن، `source_ref` و ارجاع دانشی/هش مشخص است.
- «عدم تطبیق با الگوی تألیفی»، «اطلاعات ناکافی»، «توقف به علت پیش‌نیاز یا فوریت» و «رد بیماری» یکی نمی‌شوند. این گزارش هیچ فرضیه‌ای را ردشده اعلام نمی‌کند.
- یافتهٔ واقعی معاینه حفظ می‌شود؛ اگر مدل فعلی آن را استفاده نمی‌کند، این محدودیت صریح می‌ماند. نبود معاینهٔ اختصاصی از صرف وجود یک معاینهٔ عمومی نتیجه‌گیری نمی‌شود.
- دادهٔ غایب در پرونده، از داده‌ای که در قرارداد فعلی اصلاً قابل‌ثبت نیست، جداست. برای سؤال موجود، شناسه/شماره و نوع اقدام بازبینی مشخص می‌شود. امتناع یا پاسخ نامعلوم خودکار دوباره پرسیده نمی‌شود.

این اصلاح، **توسعهٔ الگوریتم تشخیصی، افزودن بیماری جدید یا افزایش دقت بالینی نیست**. هدف آن قابل‌ممیزی‌کردن استدلال محدود فعلی و جلوگیری از برداشت قوی‌تر از داده است. قواعد خطر و توقف برای افزایش ظاهری پوشش برداشته نشده‌اند؛ Clinical Safety Rule Engine موجود همچنان مرجع عملیاتی است.

## پرونده‌های چالشی و محک مستقل

[ده پروندهٔ ساختگی](examples/orthopedic-reasoning-review-cases-v1.json) شامل درد مزمن، سابقهٔ آسیب، جراحی قبلی، معاینهٔ ثبت‌شده، درد صفر، هم‌پوشانی الگوها، پاسخ نامعلوم، تصویر تأییدنشده، اطلاعات خطر و تعارض منابع‌اند. بخش `clinician_reference` در همهٔ موارد **در انتظار بررسی مستقل** است؛ مرجع صحیح از خروجی مدل ساخته نشده است.

[گزارش تولیدشده از اجرای واقعی](ORTHOPEDIC_REASONING_CHALLENGE_REPORT_FA.md) نقش سؤال‌ها، مقایسه‌های چالشی و شواهد هر پرونده را نشان می‌دهد. تفاوت یا ثبات خروجی بین دو پرونده به‌تنهایی خطای تشخیص واقعی را ثابت نمی‌کند؛ این مقایسه‌ها ضعف پوشش و نیاز به قضاوت متخصص را آشکار می‌کنند.

معیار مرحلهٔ بالینی بعد باید مرجع متخصص برای پرونده، افتراق‌های قابل‌قبول، موارد نبایدازقلم‌بیفتد، دادهٔ لازم برای تمایز و اقدام مناسب بعدی باشد. سنجش روی پرونده‌های کنارگذاشته‌شده از تألیف قواعد، ثبت اختلاف پزشکان و بررسی خطا لازم‌اند. تعداد تست نرم‌افزار جای این مرجع را نمی‌گیرد.

## قرارداد و اجرا

قرارداد افزایشی `4b-mos.knee-reasoning-review` نسخهٔ `1.0.0` است. مسیر زیر همان پرچم پیش‌فرض غیرفعال `ORTHOPEDIC_PREVIEW_ENABLED`، نقش‌های `admin`/`physician` و `Cache-Control: no-store` را دارد:

```text
POST /api/v1/knowledge/orthopedics/knee/interview-tree/reasoning-review
```

ورودی همان زمینهٔ ساختاریافتهٔ فعلی است. قرارداد مشترک Integration، بستهٔ دانش، انتخاب سؤال و assessment موجود تغییر ناسازگار ندارند. هیچ رکورد بیمار، Registry، تأیید پزشکی یا قانون ایمنی فعال ایجاد نمی‌شود. دانش جدیدی به Approved نرفته و محتوا همچنان Draft است.

اجرای محلیِ بدون شبکه و بدون ثبت پایگاه داده:

```bash
python -B -m backend.tools.orthopedic_reasoning_review_demo
python -B -m backend.tools.orthopedic_reasoning_review_demo --write-report docs/ORTHOPEDIC_REASONING_CHALLENGE_REPORT_FA.md
python -B -m pytest backend/tests/test_orthopedic_reasoning_review.py -q
```

حالت پیش‌فرض فقط خلاصه چاپ می‌کند؛ نوشتن گزارش نیازمند گزینهٔ صریح است. وضعیت واقعی تست و CI برای هر Commit در PR ثبت می‌شود. نسخهٔ آفلاین ۰٫۲ قبلی، موتور بالینی کامل نشده و این گزارشِ سمت سرویس هنوز در رابط آن جایگزین نشده است. فایل دانلود پایدار قبلی بدون تغییر باقی می‌ماند.
