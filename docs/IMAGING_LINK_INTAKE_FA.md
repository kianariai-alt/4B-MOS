# دریافت چندقالبی از مرکز تصویربرداری و شواهد پزشکیار

شاخهٔ `feature/imaging-auto-intake` روی نسخهٔ `cb5feac7` از PR۵۳ بنا شده است.
در main ادغام نشده و هیچ Migration یا دسترسی به دیتابیس واقعی ندارد. موتور
ایمنی، هستهٔ دانش ارتوپدی و قرارداد هستهٔ یکپارچه‌سازی تغییر نکرده‌اند.

## رفتار این نسخه

دکمهٔ «تشخیص لینک و دریافت» یک پاسخ HTTPS را بدون فرض پسوند یا MIME دریافت
می‌کند. فایل PDF با نام `.dcm` همچنان PDF شناخته می‌شود. HTML صفحهٔ مرکز
مرورگر خصوصی را باز می‌کند؛ پاسخ 401/403 نیز به ورود در صفحهٔ مرکز هدایت می‌شود.
اصل HTML برای ذخیره باقی می‌ماند، ولی در نمایشگر محلی اجرا نمی‌شود.

بیمار کد، رمز یا OTP را در صفحهٔ خود مرکز وارد می‌کند. دریافت خودکار در هر
۱۵۰۰ میلی‌ثانیه فقط لینک‌های قابل مشاهدهٔ دانلود/Export را جست‌وجو می‌کند.
نشست و کوکی در همان مرورگر off-the-record می‌ماند. حداکثر هشت URL دانلود از
همان HTTPS origin، به‌ترتیب و بدون تکرار، در هر جلسه آغاز می‌شود. دکمهٔ توقف
دریافت خودکار و دانلود دستی مرورگر در دسترس‌اند. discovery هیچ input value،
رمز، cookie یا متن کامل صفحه را نمی‌خواند، فرم ارسال نمی‌کند و API حدس نمی‌زند.

در مراکزی که دانلود پشت دکمهٔ JavaScript، iframe، blob، origin دیگر یا API
اختصاصی است، دانلود دستی در همان مرورگر و سپس adapter اختصاصی لازم است.
لینک‌های blob/data فقط از مسیر دانلود خود مرورگر دریافت می‌شوند؛ robot برای
آن‌ها نشانی حدس نمی‌زند. ورود خودکار همگانی، دور زدن CAPTCHA، تطبیق واقعی با
تمام PACSها و دریافت تضمینی همهٔ فایل‌های هر Study در این نسخه انجام نشده‌اند.

## دریافت فایل با پردازش آن یکسان نیست

مسیر `download_bytes` نسبت به نوع فایل محدودیت ندارد؛ فایل ناشناخته و حتی
فایل خراب نیز برای ذخیرهٔ دستی باقی می‌ماند. محدودیت حجم و TLS همچنان برقرار
است. تشخیص magic bytes فقط برای هدایت پردازش است؛ سلامت فایل را اثبات نمی‌کند.

| محتوای دریافتی | رفتار فعلی |
| --- | --- |
| DICOM و ZIP دارای DICOM | متادیتا، کنترل Study/Series، کنترل داده با نسخهٔ قواعد، سپس حجم و MPR برای پروفایل پشتیبانی‌شده |
| PDF | دریافت و نمایش محلی Qt PDF؛ OCR، استخراج گزارش و تفسیر پزشکی انجام نمی‌شود |
| PNG/JPEG/GIF/TIFF/BMP/WebP | دریافت و نمایش محلی تصویر؛ GIF/TIFF نخستین فریم/صفحه، بدون ادعای حجم سه‌بعدی |
| MP4/MOV/HEIF، AVI، Matroska/WebM، MPEG | تشخیص خانوادهٔ container، دریافت و ذخیره؛ پخش/استخراج فریم و تحلیل ویدئو هنوز متصل نیست |
| NIfTI 1/2، NIfTI.gz، NRRD و MetaImage | تشخیص، دریافت و ذخیره؛ پردازشگر حجم مستقل هنوز لازم است |
| ZIP، GZIP و TAR | بررسی محدود فهرست محتوایی بدون استخراج روی دیسک؛ کنترل traversal، symlink، شمار و بسط |
| RAR و 7z | دریافت و تشخیص؛ decoder اختصاصی و بررسی archive هنوز لازم است |
| XML، متن، JSON-like، RTF، OLE و Office ZIP | دریافت و هدایت به پردازشگر سند؛ متن یا macro اجرا نمی‌شود |
| ناشناخته، executable یا آرشیو نامعتبر | نگهداری به‌عنوان ورودی قرنطینه‌شده؛ فقط ذخیرهٔ دستی، بدون اجرا یا پردازش بالینی |

منوی «فایل‌های دریافت‌شده» اصل هر فایل را با نام خنثی پیشنهادی
`medical-download.bin` ذخیره می‌کند؛ کاربر می‌تواند نام/پسوند مناسب انتخاب کند.
فایل خام ممکن است هویت بیمار داشته باشد و ناشناس‌سازی نشده است. فایل موقت
مرورگر پس از snapshot حذف می‌شود. مجموع payloadهای نگهداری‌شده در RAM حداکثر
۵۱۲ MiB است؛ قدیمی‌ترین ورودی با عبور از این سقف کنار گذاشته می‌شود. آغاز
ورودی دستی/مرکز جدید فهرست قبلی را خالی می‌کند. گزارش JSON شامل نام فایل،
URL، رمز یا متن گزارش نیست؛ فقط قالب، اندازه، hash، شمار قالب‌های درون آرشیو
و نتایج کنترل داده است. Hash هم ناشناس‌سازی یا اثبات هویت/مجازبودن دریافت نیست.

بررسی آرشیو حداکثر ۵۴۴ عضو، ۵۱۲ MiB مجموع اندازهٔ اعلام‌شده، ۶۴ MiB بررسی
محتوا در هر سطح و دو سطح recursion دارد. رسیدن به سقف بررسی با issue ثبت
می‌شود؛ بسط بیش از سقف GZIP یا ورودی خراب قرنطینه می‌شود. هیچ فایل آرشیوی روی
دیسک استخراج و هیچ برنامه، macro، HTML یا مدل serialized اجرا نمی‌شود.
مرورگر و parser سند همچنان باید به‌روزرسانی و در نسخهٔ عملیاتی ایزوله شوند.

## کنترل داده و پزشکیار

`ReceivedArtifact.report()` از همان `RuleBasedDecisionAdapter` موجود استفاده
می‌کند. فعلاً وجود تمام acquisition و تطبیق هویت بیمار اثبات نشده و اطلاعات
معاینه/بازبینی بالینی هم از یک فایل قابل استنتاج نیست؛ بنابراین نمونهٔ معتبر
هندسی نیز `needs_data` دارد. نتیجه شامل hash قواعد، ورودی و trace است؛ خروجی
گزارش رادیولوژی، segmentation، تشخیص یا توصیهٔ جراحی نیست.

API جدید فقط‌خواندنی:

```text
GET /api/v1/visits/{visit_id}/physician-copilot/imaging-evidence
Authorization: Bearer <4B-MOS access token>
```

فقط admin/physician می‌توانند آن را بخوانند؛ cache غیرفعال است. سرویس موجود
ClinicalContext ابتدا تمامیت گزارش‌های جاری را کنترل می‌کند. فقط گزارش imaging
نهایی‌شده با finalizer، متعلق به همان ویزیت، به خروجی می‌رسد. پیش‌نویس، گزارش
superseded یا entered-in-error و گزارش آزمایشگاهی کنار گذاشته می‌شوند. هر گزارش
شناسه، نسخه و hash محتوای منبع و هر پاسخ hash context و evidence دارد.

این داده برای زمینهٔ مشاوره، غربالگری و بازبینی تشخیص افتراقی در دسترس پزشکیار
است. متن گزارش «داده» است و دستور اجرایی برای مدل نیست. API تشخیص افتراقی تولید
نمی‌کند و یافتهٔ تأییدنشدهٔ مدل را دریافت یا تأیید نمی‌کند. وجود گزارش final نیز
به معنای اثبات اتصال آن به فایل دریافتی نیست (`image_to_report_binding_verified=false`).

اتصال خودکار payload دسکتاپ به پرونده هنوز وجود ندارد. مسیر بعدی باید storage
محافظت‌شده، رضایت و کنترل دسترسی، تطبیق هویت و سمت/عضو، ثبت منشأ acquisition،
OCR/گزارش استخراج‌شده به‌صورت پیشنهاد، بازبینی پزشک و ثبت از lifecycle فعلی را
اضافه کند. این نسخه عمداً مجوز تأیید گزارش را از ورودی فایل یا مرورگر نمی‌گیرد.
Clinical Safety همچنان مستقل اجرا می‌شود.

## اجرا و آزمون

```bash
python -m pip install -r backend/requirements-imaging-desktop.txt
python -m unittest discover -s backend/tests/imaging_desktop -v
python -m backend.tools.imaging_intake_demo --output /tmp/imaging-intake.json
# وابستگی‌های API و تست مطابق requirements.txt و requirements-dev.txt نیز لازم‌اند:
ENVIRONMENT=test DATABASE_URL=sqlite:// python -m pytest backend/tests/test_imaging_evidence.py backend/tests/test_physician_copilot.py backend/tests/test_clinical_context.py -q
```

نمونهٔ قابل بررسی در `docs/examples/imaging-intake-synthetic.json` فقط شامل
DICOM تولیدشده و signatureهای ساختگی سایر قالب‌ها است؛ signature fixture به
معنی سند/ویدئوی قابل نمایش نیست. تست رابط Qt، PNG و PDF واقعاً قابل decode
تولید می‌کند و نمایش واقعی آن‌ها و دریافت مرورگر تا importer را می‌آزماید.
آزمون driver خودکار از DOM واقعی و download spy با origin ساختگی استفاده
می‌کند؛ جای آزمون ورود و سازگاری با مرکز واقعی را نمی‌گیرد.

هیچ لینک یا رمز واقعی مرکز و هیچ فایل واقعی بیمار در نمونه‌ها و CI استفاده نشده است.
